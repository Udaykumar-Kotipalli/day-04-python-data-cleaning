# Day 04 — Retail Data Cleaning with Python & Pandas

> A reproducible data-cleaning workflow that transforms intentionally messy retail-order data into an analysis-ready dataset and produces an auditable quality report.

## Overview
Real-world datasets can contain duplicate identifiers, inconsistent text, invalid dates, missing values, and impossible numeric values. This project uses Python and Pandas to detect and address these issues before calculating sales metrics.

**Dataset notice:** all records are synthetic and intended for portfolio practice. They do not represent real customers or a real company.

## Objectives
- Inspect common data-quality issues and quantify them.
- Standardize text and convert dates/numeric fields safely.
- Detect duplicate order IDs and invalid sales inputs.
- Apply explicit, reproducible row-retention rules.
- Recalculate gross and net sales from source fields.
- Export a cleaned dataset, quality report, and summary tables.

## Dataset Fields
`order_id`, `order_date`, `customer_name`, `email`, `city`, `sales_channel`, `product_category`, `product`, `quantity`, `unit_price_inr`, `discount_rate`, `gross_sales_inr`, and `net_sales_inr`.

The 1,000-row raw dataset deliberately includes duplicate IDs, missing values, whitespace/casing inconsistencies, malformed dates and emails, non-positive quantities/prices, and out-of-range discounts.

## Cleaning Method
1. Trim whitespace and standardize selected categorical fields.
2. Parse dates and coerce invalid numeric values to missing.
3. Report duplicate IDs and common validation failures.
4. Keep the first occurrence of duplicate order IDs.
5. Exclude rows with invalid IDs/dates, non-positive quantities/prices, invalid discounts, or missing product/category.
6. Recalculate `gross_sales_inr = quantity × unit_price_inr` and `net_sales_inr = gross_sales_inr × (1 − discount_rate)`.
7. Preserve missing descriptive fields using `Unknown` or `Missing`.
8. Export the cleaned data, quality report, KPI summary, and grouped CSVs.

## Outputs

- `data_quality_report.json` — issue counts, rows removed/retained, and retention rate.

- `sales_by_city.csv` — city-level order counts and net sales.
- `monthly_sales.csv` — monthly orders and net sales.

## Business Questions
- Which category and city lead by net sales?
- How many rows were removed, and why?
- What quality issue is most common?
- How does sales performance vary by month?
- When should invalid rows be removed versus corrected or imputed?

## Assumptions and Limitations
- Duplicate order IDs are treated as duplicates and the first row is retained; a real pipeline should validate this against source-system rules.
- Invalid core sales inputs are excluded rather than imputed, which may bias results if missingness is systematic.
- Email validation checks basic format only, not whether an address exists.
- The dataset excludes taxes, shipping, cost of goods sold, and detailed returns/refunds.
- Findings apply only to this synthetic dataset.
